读：把数据带进寄存器

load 发起读请求。先确认地址和权限，再选择 cache 或前递数据；慢请求则继续等待外部返回。

写：让数据正确地落地

store 的地址和数据可分开就绪，进入队列、等允许执行，再合并、更新 cache 或发往外部。

守秩序：维护一致与正确

乱序执行要检查依赖，cache 要补行和替换，多核还要响应 snoop、维护缓存的一致状态。

理解类比把 LSU 想成“取件与发货中心”：流水线负责受理任务，队列负责记账与等待，D-cache 是近处的货架，BIU 是通向外部仓库的接口。类比只解释分工，不规定真实硬件时序。

先认清八位协作者。点击图中的模块，查看它做什么、向 LSU 发送什么，以及收到什么。

LSU↔BIU↔外层 cache / 一致性互连↔更远的内存系统后两者是系统层次示意

示例假设地址映射、p42 和数据值为教学设置；每步代表一个解释事件，不是一个时钟拍。TLB miss、前递、miss 返回及补行受真实握手影响，不能把动画当作 RTL 仿真波形。

这条 ld 的数值到底怎么算？
ld x5, 24(x10) x10 = 0x0000_0000_0000_1000 VA = 0x1000 + 24 = 0x1018 示例映射：VA 页 0x1000 → PA 页 0x80001000 PA = 0x80001018 读取字节：PA 0x80001018 ～ 0x8000101f（共 8 字节） 示例结果：p42 ← 0x1122334455667788

十进制 24 就是十六进制 0x18。0x1018 能被 8 整除，本例对齐且不跨页。64 字节 cache line 从 0x80001000 开始，所以这些字节在同一行。小端示例中，按地址递增的字节为 88 77 66 55 44 33 22 11。ld 读取整个 64 位结果；lb / lh / lw 则还要按指令做符号扩展，lbu / lhu / lwu 做零扩展。

04

“读完了”，到底指哪一件事？

理解 C910 时，这一步比背缩写更重要。不要把完成回报、顺序推进、数据写回和缓存补行混成一件事。

指令状态线：我可以报告到哪一步？

cmplt 向 RTU 报告执行状态，包含正常或异常信息。RTU 另有 commit 广播和顺序退休逻辑。普通非强序 load 的 cmplt 可能早于数据返回。

结果数据线：目的寄存器有值了吗？

data writeback 表示目的物理寄存器收到数据，后续消费者才能用这个值。C910 的 PST 独立追踪退休与写回，允许部分 load 先退休、后写回。

RTL 支持普通 load miss 可能出现的时序关系
DA 创建 RB记住请求地址与目的寄存器
WB 先发 cmplt数据暂时还没写回
RTU 可以先退休符合顺序与其他控制条件时
数据稍后写回RB → LD_WB → 目的寄存器

这只是实现允许的一种关系，并不规定固定延迟。反过来，数据先写回、因更老指令阻挡而稍后退休也可以。commit 广播与这里的 cmplt / retire 各有条件，也可能更早发生。flush 收尾还会等待已退休 / 已 commit 操作的数据义务完成。

看到的事件可以确认什么需要继续分清什么
cmpltLSU 给 RTU 的完成状态通路有效。可能带异常；不保证本条 load 的数据已经写回。
commit 广播RTU 向 LSU 发送了相应 IID 的 commit 控制信息。LQ 可按它清除记录，SQ / RB 等也使用它；不要与 cmplt 或 retire 信号互换。
retireRTU 顺序退休逻辑按当前条件处理了指令。当前实现允许退休后仍有未返回的数据，由 PST 等结构跟踪。
data writeback本条结果写入目的物理寄存器，并回报相应写回有效。这与本条 cmplt 的拍次不必相同；数据通路和状态通路有独立仲裁。
linefill 完成LFB 的整行补入工作完成。load 可从返回通路经 RB 取数；不用把所有 miss 都理解成补满后重新读 L1。

TLB miss 和 cache miss 各缺什么？

前者缺可用的地址翻译，要等 MMU 并重发；后者已有可用物理地址，但 L1 数据不在，要由 RB / BIU 等取回。page fault 则是翻译或权限检查失败，走异常路径。

遇到老 store，一定能前递吗？

要看 store 是否更老、地址和字节覆盖是否匹配、数据是否准备好、依赖是否单一。不满足时可能重发或等唤醒；不能只看地址相等。

LQ 和 RB 为什么都要存在？

LQ 记住 load 的顺序关系，便于发现 RAW / RAR 推测冲突。RB 保存读请求和数据目的地，能够在请求等待、load 甚至已退休之后继续完成数据工作。

本例之外，还会遇到哪些支路？

非对齐 / 跨边界、不可缓存与强序访问、LR/SC 与 AMO、fence、总线错误、snoop 冲突等都有额外控制。本指南给出定位入口，详细行为仍须看对应条件。

05

看到缩写，随手查一下。

先理解作用，再去看具体信号。AG / DC / DA / WB 在本页按阶段用途解释；名字本身不能替代源码里的实际行为。

LSU
Load / Store Unit，负责 CPU 的数据访存。
load / store
load 从存储系统读到寄存器；store 把寄存器数据写入存储系统。
VA / PA
虚拟地址 / 物理地址。程序给出的地址经 MMU 翻译后访问存储层次。
TLB / μTLB
地址翻译的缓存 / 更靠近访问流水的小型翻译缓存。
tag / index / offset
tag 确认是哪一行；index 选择一组；offset 选择行内哪几个字节。
cache line / way / bank
缓存搬运和维护的行单位 / 组中的候选位置 / 数据阵列分块。本配置一行 64 字节、两路。
IID / preg
指令身份编号 / 物理目的寄存器编号。分别用于跟踪指令与写回目的地。
LSIQ / SDIQ
IDU 中的访存任务发射队列 / store 数据发射队列，都在 LSU 外。
forward / bypass
前递 / 旁路：直接采用已经可用的新数据，减少等待。
replay / restart
这次尝试遇到条件不满足，保留或重新唤醒任务再执行。
flush
清除或恢复受到错误推测、异常等影响的流水 / 队列状态，具体保留规则由实现决定。
AR / R / AW / W / B
读地址 / 读返回 / 写地址 / 写数据 / 写响应通路。AC / CR / CD 用于一致性请求、响应和数据。

依赖检查中的 RAW / RAR：RAW 是“写后读”，更晚的 load 应看到更早 store 的正确值；RAR 是“读后读”，硬件也要在乱序、snoop 等情形下维护所需的读顺序。本核 LQ entry 中有两类检查；具体触发条件不要只靠缩写推导。
